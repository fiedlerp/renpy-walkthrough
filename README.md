# renpy-walkthrough

Generate a walkthrough / game-flow graph from a Ren'Py game.

## Overview

`parse_rpy.py` is a script template that uses the **Ren'Py engine** to parse
`.rpy` script files and extracts the game's structure as a directed graph.
Nodes in the graph are named *labels*; edges represent control-flow transfers
such as `jump`, `call`, and `menu` choices.

The output is a JSON document that can be consumed directly or fed into graph
visualisation libraries such as
[networkx](https://networkx.org/),
[Gephi](https://gephi.org/), or [d3.js](https://d3js.org/).

## Getting started

Ren'Py is included as a **git submodule** at `renpy-sdk/` (tracked at
[renpy/renpy](https://github.com/renpy/renpy)), so no separate SDK download
is required.

### Clone (recommended)

```bash
git clone --recurse-submodules https://github.com/fiedlerp/renpy-walkthrough.git
cd renpy-walkthrough
```

### Already cloned without `--recurse-submodules`?

```bash
git submodule update --init
```

### Updating Ren'Py to the latest commit

```bash
git submodule update --remote renpy-sdk
git add renpy-sdk
git commit -m "Update Ren'Py submodule"
```

## Requirements

### Python

Python 3.9 or newer.

### Optional dependencies

```
pip install networkx matplotlib   # for graph analysis / visualisation
```

## Usage

```bash
# Parse a game directory – the bundled submodule is used automatically
python parse_rpy.py /path/to/my-game

# Write the graph to a file
python parse_rpy.py /path/to/my-game --output graph.json

# Override the Ren'Py path (env var or flag)
export RENPY_SDK=/path/to/renpy-sdk
python parse_rpy.py /path/to/my-game

python parse_rpy.py /path/to/my-game --renpy-sdk /path/to/renpy-sdk
```

### SDK resolution order

`parse_rpy.py` resolves the Ren'Py SDK in this order (first match wins):

1. `--renpy-sdk PATH` command-line argument
2. `RENPY_SDK` environment variable
3. `renpy-sdk/` submodule bundled with this repository

## Output format

```json
{
  "nodes": {
    "start":        { "filename": "game/script.rpy", "linenumber": 3 },
    "chapter_one":  { "filename": "game/script.rpy", "linenumber": 9 }
  },
  "edges": [
    { "from": "start",       "to": "chapter_one", "type": "jump",
      "filename": "game/script.rpy", "linenumber": 7 },
    { "from": "chapter_one", "to": "good_path",   "type": "menu",
      "choice": "Take the left path",
      "filename": "game/script.rpy", "linenumber": 15 }
  ]
}
```

### Edge types

| Type   | Ren'Py statement        |
|--------|-------------------------|
| `jump` | `jump <label>`          |
| `call` | `call <label>`          |
| `menu` | a choice inside `menu:` |

## Example

An annotated example script is included in [`example/script.rpy`](example/script.rpy).

```bash
# No extra setup needed – the submodule provides Ren'Py automatically
python parse_rpy.py example/
```

```json
{
  "nodes": {
    "start":       { ... },
    "chapter_one": { ... },
    "flashback":   { ... },
    "good_path":   { ... },
    "bad_path":    { ... },
    "good_ending": { ... },
    "bad_ending":  { ... },

```

## Extending the template

* **networkx graph**: uncomment the `build_networkx_graph()` function in
  `parse_rpy.py` to obtain a `networkx.DiGraph` that you can analyse, layout,
  and render with `matplotlib`.
* **Filter internal labels**: skip labels whose names start with `_` – these
  are auto-generated by Ren'Py for translation and internal use.
* **Richer nodes**: extend the node metadata with dialogue counts,
  character lists, or image names by walking additional AST node types such as
  `renpy.ast.Say`, `renpy.ast.Scene`, and `renpy.ast.Show`.
* **Export formats**: call `networkx.write_graphml()` or
  `networkx.write_gexf()` on the DiGraph to export to Gephi-compatible formats.
